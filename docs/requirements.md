# 木搭图（Modatu）需求分析文档

> 版本：v0.1（需求梳理定稿）
> 日期：2026-11-13
> 状态：已与产品负责人逐轮确认（grilling 3 轮，25 问）

---

## 1. 项目背景与定位

家庭用户在首次定制家具后，常有不满意或想追加定制柜体、家具的需求。普通用户缺乏家具设计经验，仅凭草图与商家沟通无法直观看到成品效果。

**木搭图（Modatu）** 是一个 Web 端铝型材家具设计工具：用户通过自然语言描述或手动操作，得到可编辑的参数化 3D 模型，并最终导出可下单的配置清单。

### 1.1 目标用户

| 用户群 | 描述 | 优先级 |
|---|---|---|
| A. 零经验普通用户 | 想要"说几句话就得到柜子"，不懂型材规格 | **主要** |
| B. 进阶 DIY 玩家 | 熟悉 2020/3030 等型材规格，做机架、置物架 | 次要（自然覆盖） |

### 1.2 产品阶段边界

- **第一期（本文档范围）**：Web 端，铝型材框架家具设计；AI 生成/修改在编辑器完成后接入（见 §9 里程碑）。
- **第二期**：手机 App、充值使用官方 LLM、微信渠道对接、商家 SKU 映射、精确结构力学计算、设计文件导出/导入等（见 §12）。

---

## 2. 核心用户主线（P0 验收场景）

> 普通用户输入一句话描述（如"1.2 米宽、2 米高的三列书架"）→ LLM 生成结构化模型 → 3D 预览中受约束微调 → 导出带水印配置清单。

一期**不集成任何邮件系统、不做商家发送**；"下单"链路的终点是**带水印清单导出**（PDF）。商家对接方式二期再探索。

---

## 3. 功能需求

### 3.1 3D 预览与编辑器（受约束参数化编辑）

- 基于 Three.js 自研渲染（不用重型 CAD 内核；铝型材为标准型材截面 + 长方体组合，参数化渲染足够）。
- **受约束编辑**，非自由 CAD：
  - 用户在模型/模块基础上调整整体尺寸（宽/深/高，单位 mm，切割精度 0.5mm）；
  - 增删立柱、层板、封板；
  - 更换型材规格（仅限知识库内规格）；
  - 简单拖拽定位 + 表单化参数输入为主。
- 封板（侧板、背板、层板）与桌面：**自由定尺寸矩形板**，从预设材质/厚度/颜色中选择，自动进入清单（商家按尺寸裁切）。
- 设计数据**仅云端保存**（登录后自动保存）；不做本地导入/导出。
- AI 修改采用 **diff 预览 + 版本历史**：
  - AI 修改先高亮变更，用户点"应用"才生效；
  - 自动保存版本历史，可一键回退。

### 3.2 AI 生成与修改

- LLM 输入用户自然语言，输出**结构化参数模型（JSON）**：型材规格、数量、切割长度、连接方式、封板参数等；不生成效果图（预览界面即所见）。
- 模型必须只引用知识库中存在的规格/连接件；超出能力的请求（如"铝制旋转门"）：**尽量近似实现 + 明确列出未满足项**，不直接拒绝。
- 接入方式（一期仅 BYOK）：
  - 用户自配 API Key，**仅支持 OpenAI 兼容协议**（base_url + api key + model 名）；
  - 官方计费渠道（充值）二期。
- **接入时机**：编辑器与内部数据基本就绪后再开发（里程碑 M5，见 §9），开发期用内部测试数据 + 手动编辑驱动。

### 3.3 知识库

1. **材料规格库**：国标通用铝型材规格（2020/2040/3030 等）、角码、T 型螺栓/螺母、封板材质厚度等；一期人工录入，支持后台维护。
2. **材料特性与安全规则库**：承载特性、力矩/重心相关的**规则化提示**（例：跨度超过 X 建议加立柱或换重载型材；层板承重查表提醒）。一期不做精确结构力学计算（挠度/应力校核/有限元为二期演进卖点）。

### 3.4 配置清单与水印导出

- 根据模型自动生成清单：型材规格、切割长度与数量、连接件、封板（尺寸+材质）。
- 单位统一 mm，切割精度 0.5mm。
- **导出格式：仅 PDF**（Excel 二期，易篡改水印意义不大）。
- 水印：用户 ID + 昵称 + 生成时间戳，半透明斜向平铺全页；页脚含软件标识。

### 3.5 账号与登录

- **开发阶段**：用户名 + 密码登录（由编译/部署 flag 控制，上线关闭）。
- **生产环境**：
  - 仅微信扫码登录（需微信开放平台资质，接入时间视资质办理进度）；
  - 保留一个**独立的隐藏登录页**（手动输入 URL 访问），支持账号密码登录，用于线上测试。
- 游客可试用（浏览/编辑），保存设计与导出需登录。

### 3.6 商家配置（一期降级）

- 一期**不实现**商家发送/邮件系统；
- 商家列表管理（后台维护商家信息 + 用户下单时选择/手填邮箱）的设计保留在二期，待商家接入方式探索清楚后再细化。

### 3.7 后台管理（一期最小化）

一期只做支撑性最小后台，详细设计后置：

1. 材料规格库维护（一期必须）；
2. 用户管理（一期必须）；
3. 商家管理、发送记录 → 二期；
4. 用户设计查看（客服支持用）→ 二期（隐私与存储成本）。

## 4. 技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | React + Three.js（自研渲染） | 铝型材参数化模型，无需 CAD 内核 |
| 后端 | Node.js（NestJS）+ PostgreSQL | 前后端同语言，降低维护成本 |
| 部署 | 一期单台云服务器 + Docker Compose | 简单可控 |
| 手机复用 | **性能优先**：Web 优先上线；渲染层做**抽象隔离**（独立渲染模块、模型层与 UI 层解耦），若 WebView 性能不达标，接受手机端另起原生实现，仅复用模型/数据层 | 不为复用牺牲 Web 性能 |
| LLM | OpenAI 兼容协议 BYOK | 官方计费二期 |

---

## 5. 非功能需求（初步）

- **性能**：一期先以"明显优于同类（嘉立创 3D 下单等）的流畅度"为目标，上线后实测再定量化指标与优化方案（实例化渲染、拖拽降级等手段作为储备，暂不承诺具体帧率/规模数字）。
- 浏览器：一期支持桌面 Chrome/Edge 最新版。
- 数据安全：用户 API Key 加密存储；设计数据云端持久化。

---

## 6. 数据模型要点（开发前细化）

- 结构化模型 JSON Schema：项目 → 框架（型材件列表：规格/长度/位置/连接）+ 封板件列表 + 版本历史。
- 知识库表：型材规格、连接件规格、板材材质/厚度、安全规则。
- 用户表：账号（dev 账密 / 微信 unionid）、加密的 LLM 配置。

---

## 7. 单位与精度约定

- 全站长度单位 **mm**；切割精度 **0.5mm**。

---

## 8. 明确不做（一期）

- ❌ 邮件系统 / 任何商家发送通道
- ❌ 手机 App
- ❌ 充值与官方 LLM 计费
- ❌ 微信以外分享、设计文件导入导出
- ❌ 精确结构力学计算（有限元）
- ❌ 自由 CAD 级编辑（布尔运算等）
- ❌ Excel 清单导出

---

## 9. 第一期里程碑

| 里程碑 | 内容 | 可演示成果 |
|---|---|---|
| M1 | 知识库 + 数据模型 + 基础后台（规格库维护、用户管理）+ 登录（dev 账密） | 后台可维护规格库，可登录 |
| M2 | 3D 预览 + 受约束编辑器 | 手动搭出一个铝型材书架并调参 |
| M3 | 清单生成 + 带水印 PDF 导出 | 从模型一键导出清单 |
| M4 | 云端保存 + 版本历史 | 设计自动保存、可回退 |
| M5 | AI 接入：BYOK（OpenAI 兼容）生成/修改、diff 预览、近似实现+未满足项提示 | P0 主线全流程跑通 |

> 注：LLM 晚于编辑器开发——先用内部数据把编辑器与清单做扎实，具备内部数据后再设计 LLM 接入。

## 10. 二期及以后（Backlog）

- 手机 App（性能优先决定复用策略；渲染层抽象已预留）
- 充值 + 官方 LLM 计费渠道
- 微信生态：公众号/小程序、微信发送清单给商家
- 商家对接完整方案（商家列表、SKU 映射、下单链路）
- Excel 清单导出
- 精确结构力学校核（挠度、应力）作为进阶卖点
- 设计文件本地导入/导出、用户设计查看（客服）
- 更多材质：板材家具、亚克力等

---

## 11. 开放问题（不阻塞一期开发）

1. 微信开放平台资质办理时间点（影响生产登录上线形式）。
2. 性能量化指标（等一版本实测后回头补 §5）。
3. 商家接入模式（自营 / 第三方平台 / 线下门店）。

## 12. 决策记录（ADR 摘要）

| # | 决策 | 理由 |
|---|---|---|
| 1 | AI 输出结构化 JSON 而非效果图 | 支撑编辑与清单生成；预览界面即效果 |
| 2 | 受约束参数化编辑而非自由 CAD | 目标用户 A 类门槛；AI 修改与清单可靠 |
| 3 | Three.js 自研渲染 | 型材结构简单，无需 CAD 内核，生态最好 |
| 4 | 手机复用：性能优先，可接受双端两套代码 | 不为代码复用牺牲 Web 性能 |
| 5 | 一期仅 BYOK（OpenAI 兼容） | 开发调试即需；计费后置 |
| 6 | 一期无邮件/商家发送 | 商家接入模式未定，先到导出为止 |
| 7 | 登录：dev flag 账密 + 线上隐藏登录页 | 资质不阻塞开发，线上仍可测试 |
| 8 | 知识库人工录入国标规格 + 后台维护 | 商家 SKU 映射二期 |
| 9 | 力学校验走规则化提示 | 一期可控，精确计算二期演进 |
| 10 | 设计仅云端保存 | 无导入目标场景 |
