# Spec 05 — BOM 清单生成与水印 PDF 导出

## Problem Statement

用户设计完成后需要一份商家可直接理解的采购清单（型材切割规格、连接件、板材），并且因为清单最终要发给商家比价/下单，平台需要防止清单被冒用或去水印转发。

## Solution

从设计模型一键生成 BOM 清单（纯函数：模型 → 清单行），并导出为带用户身份水印的 PDF。一期链路终点就是导出；不集成任何邮件/商家发送系统。

## User Stories

1. 作为用户，我想把当前设计一键生成 BOM 清单，以便交给商家采购。
2. 作为用户，我想清单中列出每种型材规格的切割长度与数量（同规格同长度合并计数），以便商家按单切割报价。
3. 作为用户，我想清单中列出所需连接件（种类与数量，按知识库的兼容矩阵与用量系数计算），以便不漏买配件。
4. 作为用户，我想清单中列出封板/桌面（材质、厚度、宽×高尺寸、数量），以便商家裁切板材。
5. 作为用户，我想导出的 PDF 带有我的身份水印（用户 ID + 昵称 + 生成时间，半透明斜向平铺），以便清单被转发时仍可追溯来源。
6. 作为用户，我想 PDF 页脚含软件标识，以便收到清单的商家知道出处。
7. 作为用户，我想清单中所有长度以 mm 显示且与设计数值一致，以便避免换算错误。
8. 作为用户，我想导出前在界面预览清单内容，以便发现漏项后再导出。
9. 作为系统，我想只有登录用户能导出（水印需要身份），以便水印可追溯。
10. 作为用户，我想切割长度自动对齐 0.5mm 精度（编辑器已保证），以便与供应商口径一致。
11. 作为用户，我想对同一设计修改后重新生成清单时得到最新结果（清单不是存储的旧快照），以便始终导出当前状态。
12. 作为商家（间接受益者），我想清单结构清晰（分组：型材/连接件/板材，各含规格列），以便快速报价。

## Implementation Decisions

- BOM 生成为**纯函数**：`design JSON → BOM 行数组`，无 IO、无状态（接缝 3）。连接件数量由知识库兼容矩阵 + 用量系数推导；推导所需输入不足（如某连接缺失兼容件）时在清单预览中标记为"无法自动计算"并提示用户回编辑器修正。
- PDF 为唯一导出格式（Excel 二期不做，决策记录：易篡改，水印意义弱）。生成在前端完成或服务端完成实施时定；水印逻辑与 BOM 生成同样做成可测的纯转换。
- 水印内容：用户 ID + 昵称 + 生成时间戳；呈现为半透明斜向平铺全页 + 页脚软件标识；规格数值区域水印不遮挡可读性（透明度实施时调）。
- 清单不持久化存储（每次由当前模型生成）；导出动作本身记录与否一期不做（无发送链路）。
- 单位与精度全局约定：mm / 0.5mm（requirements §7）。

## Testing Decisions

- BOM 纯函数为主测试面：给定模型 fixture，断言合并计数（同规格同长度）、连接件系数推导、板材行输出、缺失兼容件的标记行为。
- 精度测试：0.5mm 对齐与 mm 展示（含边界值如 1200.25 → 拒绝/校正的既定行为）。
- PDF 测试：抽取生成 PDF 的文本层断言包含水印字段（用户 ID、昵称、时间戳、页脚标识）与 BOM 关键行；不校验像素级排版。
- 无既有先例；纯函数测试模式与 spec-04 状态层测试共同构成项目测试范本。

## Out of Scope

- 邮件发送、微信发送、任何商家对接通道（决策记录 6；商家模式二期探索）。
- Excel/CSV 导出。
- 清单报价/价格列（一期无价格数据）。
- 清单多语言。

## Further Notes

- "无法自动计算的连接件"是刻意的显式失败路径：宁可清单带警告也不静默漏项。
- PDF 模板版式（表头列名、分组顺序）实施时定，本 spec 只锁定内容与水印要求。
