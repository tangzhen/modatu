# Spec 06 — AI 生成与修改（BYOK，OpenAI 兼容）

## Problem Statement

目标用户（零经验）不会从零搭模型：他们需要"说一句话就得到一个柜子"，之后用自然语言继续修改。同时 AI 产出的模型必须永远可渲染、可出清单，且用户害怕"AI 一句话把设计改坏了回不去"。

## Solution

接入 LLM（用户自配 API Key，仅 OpenAI 兼容协议）：从自然语言生成结构化设计模型 JSON；对现有模型做修改时先以 diff 预览（高亮变更），用户确认应用后才生效，且每次应用自动形成可回退版本。超出知识库能力的请求做近似实现并明确列出未满足项。

## User Stories

1. 作为用户，我想在设置中填写 API 地址（base_url）、API Key 与模型名，以便使用我自己的 LLM 账号。
2. 作为用户，我想我的 API Key 以加密方式存储且界面上不明文回显，以便密钥不被泄露。
3. 作为用户，我想输入一句自然语言描述（如"1.2 米宽、2 米高的三列书架"）生成一个初始设计模型，以便不从头搭模型。
4. 作为用户，我想对当前设计说修改指令（如"加一层层板""右边留出 30cm 挂衣区"）得到修改后的模型，以便持续迭代。
5. 作为用户，我想 AI 的每次修改先以 diff 预览呈现（高亮将变更的部件），我点"应用"才生效，以便防止 AI 改坏。
6. 作为用户，我想不应用 diff 就能放弃本次 AI 修改，以便无损拒绝。
7. 作为用户，我想 AI 修改被应用后自动生成版本记录，以便随时回退（依赖 spec-02 版本历史）。
8. 作为用户，当我提出系统做不到的需求（如"铝制旋转门"）时，我想得到一个近似实现 + 明确列出哪些需求未被满足，以便理解差异而不是被硬拒绝。
9. 作为用户，我想看到 AI 调用的进行中状态与失败提示（如 Key 无效、余额不足、网络错误），以便知道发生了什么。
10. 作为用户，我想 AI 生成的模型只使用知识库中启用的规格与连接件，以便结果必然可渲染、可出清单。
11. 作为用户，我想在 AI 生成/修改后仍能继续手动微调，以便人机接力完成设计。
12. 作为系统，我想将知识库可用规格/连接兼容数据的子集注入 prompt，以便模型输出限定在合法集合内。
13. 作为系统，我想对 LLM 返回的 JSON 做严格校验（Schema + 知识库引用 + 连接兼容），校验失败按策略重试或明确报错，以便非法输出不会进入编辑器。
14. 作为开发者，我想 LLM 调用封装在统一适配器接口之后（测试用假 LLM 替换），以便自动化测试不依赖真实网络。
15. 作为用户，我想生成的新设计也进入"我的设计"（登录后），以便与手动创建的项目同等管理。

## Implementation Decisions

- 一期仅 BYOK，仅 OpenAI 兼容协议（base_url + key + model 三要素）；官方计费充值渠道二期（决策记录 5）。
- AI 交互只产出/消费**结构化模型 JSON**，不生成效果图（预览界面即所见，决策记录 1）。
- LLM Adapter 接口（接缝 4）：`generate(prompt, catalog) → design JSON` 与 `modify(current JSON, instruction, catalog) → modified JSON（或 diff）`；diff 的计算在系统侧由新旧模型对比得出（不信任 LLM 自报 diff），保证 diff 与实际应用结果一致。
- 应用链路：LLM 输出 → Schema 校验 → 知识库引用/兼容校验 → 与当前模型计算 diff → 用户预览确认 → 应用（走编辑器状态层同一操作管道，保证撤销栈与版本历史一致）。
- 未满足需求项：LLM 被要求在输出中附带结构化的"未满足项"列表；系统侧仅展示，不二次猜测。
- 失败策略：校验失败自动重试（带错误反馈的修复提示）有限次；仍失败则向用户展示可读错误，不静默降级。
- API Key 加密存储（服务端静态加密）；前端永不明文回显（只显示掩码）。
- 接入时机：编辑器（spec-04）与内部数据就绪后开发本 spec（M5）；开发期间以 fixture 模型与手动编辑驱动其余模块联调（requirements §9 注）。
- Prompt 工程细节（模板、few-shot 示例）实施时迭代，本 spec 锁定输入/输出契约与安全链路。

## Testing Decisions

- 主测试面为 LLM Adapter 契约测试（接缝 4）：注入 canned LLM 响应，断言校验通过/失败路径、重试策略、diff 计算与应用后的最终模型（接缝 1 应用）。
- diff 一致性测试：给定的 diff 预览与实际应用结果必须一一对应（对比新旧模型计算的 diff 与应用后模型快照）。
- "未满足项"传递测试：canned 响应含未满足项时，结果界面正确呈现。
- Key 安全：仅外部行为断言（存储密文、回显掩码、日志不含密钥），不测加密实现内部。
- 真实 LLM 冒烟（生成一本架、加层板两例）列为人工验收项，不进自动化。

## Out of Scope

- 官方充值计费、用量配额、计费审计。
- 效果图/渲染图生成（多模态输出）。
- 多轮复杂对话式工作流编排（一期为"生成 + 单步修改"的简单循环）。
- 非OpenAI 兼容协议的适配（如 Anthropic 原生协议）。

## Further Notes

- 本 spec 依赖 spec-01（目录数据）、spec-02（模型/版本）、spec-04（应用管道）全部就绪，是第一期最后落地的里程碑。
- 模型输出 token 成本与用户自担的 API 费用：界面上应提示调用会消耗用户自己的配额（文案实施时定）。
