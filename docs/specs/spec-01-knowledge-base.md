# Spec 01 — 材料知识库与后台维护

## Problem Statement

用户与 AI 想设计铝型材家具，但型材截面、连接件、板材种类繁多且互不兼容；如果系统没有一个可信的"哪些规格存在、什么特性、能怎么连"的权威数据源，编辑器换规格、AI 生成模型、BOM 出清单都会产出无法实际买到/装不上的方案。

## Solution

建立平台级材料知识库：一期人工录入国标通用规格，通过后台维护（增改、停用）。知识库同时携带材料特性与安全规则数据，供编辑器的规则化安全提示使用。所有设计模型只能引用知识库中存在的规格。

## User Stories

1. 作为管理员，我想在后台新增一种铝型材规格（系列代号、截面宽高、槽宽、槽深、单位长度重量、允许切割长度范围），以便系统支持该规格的设计与下单。
2. 作为管理员，我想维护型材规格的承重参考数据（不同跨度的推荐承重），以便系统给出规则化安全提示。
3. 作为管理员，我想维护连接件目录（角码、T 型螺栓/螺母等：名称、适用槽宽、适用型材系列组合、单件所需数量系数），以便编辑器与 BOM 使用正确连接方式。
4. 作为管理员，我想维护"型材系列 × 型材系列"的连接兼容矩阵（哪两种规格之间有什么连接件可用），以便编辑器禁止不可能的连接。
5. 作为管理员，我想维护封板/桌面材质目录（名称、常用厚度列表、密度/面密度参考），以便用户选材并让 BOM 正确输出板材。
6. 作为管理员，我想维护规则化安全规则（规则类型、参数如最大无支撑跨度、提示文案模板），以便编辑器在不做精确力学计算的情况下提醒用户。
7. 作为管理员，我想停用一个规格而不是删除它，以便引用该规格的存量设计仍能打开，但新设计不再能选用。
8. 作为管理员，我想按类别和关键字搜索规格，以便在规格多起来后快速定位要维护的条目。
9. 作为管理员，我只想以管理员身份访问后台，以便普通用户无法篡改知识库。
10. 作为用户（编辑器使用者），我想在选规格时看到规格的截面尺寸与参考承重，以便做出合适选择。
11. 作为用户（编辑器使用者），我想在设计中触发规则化安全提示（如跨度超限时提示加立柱或换重载型材），以便在不懂力学的情况下避免明显不安全的结构。
12. 作为 AI 生成功能，我想通过 API 获取当前可用的规格与连接兼容数据，以便生成的模型永远只引用真实存在的规格。
13. 作为开发者，我想让知识库数据有稳定的对外读取接口（仅读、可缓存），以便前端与 AI 模块不直接依赖数据库结构。
14. 作为管理员，我想看到每个规格的启用/停用状态与最近修改时间，以便了解知识库现状。

## Implementation Decisions

- 知识库数据存 PostgreSQL，由后端统一维护；一期无自动导入，人工录入 + 后台 CRUD。
- 知识库分为四类实体：**型材规格**、**连接件（含兼容矩阵）**、**板材材质**、**安全规则**。
- 型材规格字段（概念层）：代号（如 3030）、系列、截面宽/高、槽宽、槽深、单位长度质量、允许切割长度上下限、承重参考表（跨度→推荐承重）、启用状态、时间戳。
- 连接兼容矩阵表达为：连接件记录 + "适用端面组合"（规格 A × 规格 B），编辑器与 AI 查询此矩阵决定可用连接。
- 停用采用软停用（enabled 标志），不做物理删除；引用校验只对启用的规格生效。
- 安全规则为数据驱动（规则类型 + JSON 参数 + 文案模板），由一个纯规则求值函数消费（该函数属于 spec-04 的编辑器提示模块，规则数据归本 spec 管理）。
- 对外读取接口：`GET /catalog/*` 只读接口，返回启用条目；后台管理接口要求 admin 角色。
- 后台一期仅实现知识库维护（用户管理见 spec-03）；商家管理、发送记录、用户设计查看均不做。

## Testing Decisions

- 好测试的标准：只测外部行为——通过只读 API 和后台 API 断言数据可见性、权限、停用行为；不测内部 SQL/ORM。
- 测试范围：后台 CRUD 与权限（未登录/非 admin 被拒）、停用后只读接口不再返回但存量引用不报错、兼容矩阵查询语义。
- 规则求值函数作为纯函数测试：给定知识库规则数据快照 + 设计模型，断言提示列表（属于接缝 1 的应用）。
- 绿地项目，无既有测试先例；此 spec 的 API 测试模式将作为后续 spec 的参考。

## Out of Scope

- 商家 SKU 映射、价格数据（一期无下单）。
- 精确力学计算数据（挠度/应力曲线等）。
- 知识库批量导入/导出。
- 用户侧规格自定义。

## Further Notes

- 初始录入清单（2020/2040/3030 等主流欧标系列及其常用连接件）在实施时单独确认，不阻塞本 spec。
- 规则文案模板需支持参数插值（如实际跨度值），避免写死多个相似规则。
