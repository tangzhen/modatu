# Spec 04 — 3D 预览与受约束编辑器

## Problem Statement

普通用户缺乏 CAD 经验，自由建模工具（如参考的嘉立创 3D 下单软件）上手门槛高且性能差；用户需要一个"看得懂、改得动、不卡顿"的 3D 界面来查看和微调自己的家具设计。

## Solution

基于 Three.js 自研的 3D 预览 + 受约束参数化编辑器：用户只能做预设范围的编辑（调尺寸、增删立柱/层板/封板、换规格），以表单 + 简单拖拽交互；渲染层与模型/状态层解耦，为未来手机端可能的渲染替换预留边界。

## User Stories

1. 作为用户，我想看到设计模型的实时 3D 预览（型材按真实截面、板材按真实厚度渲染），以便直观理解设计。
2. 作为用户，我想旋转、平移、缩放视角，以便从任意角度检查结构。
3. 作为用户，我想选中任意一个部件（型材/封板）并看到高亮，以便知道我在编辑谁。
4. 作为用户，我想通过表单调整整体框架尺寸（宽/深/高），以便快速改变设计规模。
5. 作为用户，我想添加立柱/层板并指定数量与位置，以便调整结构布局。
6. 作为用户，我想删除选中的部件，以便移除不需要的结构。
7. 作为用户，我想更换选中型材的规格（仅限知识库中启用的规格，并显示截面与承重参考），以便权衡承重与成本。
8. 作为用户，我想为框架添加封板/桌面（自由定尺寸矩形板，选择材质/厚度/颜色，指定所在面与位置），以便表达侧板、背板、层板与桌面。
9. 作为用户，我想通过简单拖拽在受约束方向上移动部件（吸附到栅格/槽位），以便微调布局而不破坏结构合法性。
10. 作为用户，我想所有操作通过表单输入精确数值（mm），以便不依赖拖拽精度。
11. 作为用户，我想在编辑违反结构约束时得到即时反馈（如所选两规格无兼容连接件、切割长度超出该规格允许范围），以便当下纠正而不是导出时才发现。
12. 作为用户，我想看到规则化安全提示（跨度超限建议加立柱/换重载型材、层板承重查表提醒），以便在不懂力学的情况下避免明显不安全设计。
13. 作为用户，我想撤销/重做我的编辑操作，以便大胆尝试。
14. 作为用户，我想编辑时模型始终满足设计模型 Schema 与知识库引用约束（不可能产出非法模型），以便任何时刻的模型都可以保存/导出。
15. 作为移动端访客（未来），我希望渲染层可被替换为原生实现而模型/交互逻辑复用，以便性能不足时不必重写业务。

## Implementation Decisions

- 架构分层（关键决策）：**模型状态层**（设计模型的内存状态 + 变更操作/撤销栈，纯逻辑，无 Three.js 依赖）与**渲染层**（消费模型状态绘制场景、把拾取事件转回部件 id）严格解耦。渲染层通过抽象接口与状态层通信——这是"手机端 WebView 性能不足则原生替换"的预留边界（决策记录 4：性能优先，可接受两套代码）。
- 受约束编辑的操作集合有限且固定：改整体尺寸、增删立柱/层板/封板、换规格、受约束拖拽、精确数值输入。不提供自由变换、布尔运算等 CAD 级能力。
- 部件合法性校验在状态层执行（引用规格必须启用、连接需有兼容连接件、切割长度在规格允许范围内），非法操作直接拒绝并给出原因——编辑器永远不会产出非法模型。
- 规则化安全提示：消费 spec-01 的规则数据对当前模型求值，在属性面板/提示条展示（非阻塞警告，不阻止保存）。
- 撤销/重做基于模型状态的命令栈（与版本历史不同：撤销是编辑会话内行为，版本历史是云端持久行为，见 spec-02）。
- 渲染技术：Three.js 直接使用（不深度绑定 React 渲染树）；型材用参数化几何（截面 + 挤出），板材用盒体；单位换算统一 mm→场景单位。
- 性能：一期目标是主观流畅度明显优于同类产品；具体量化指标与优化手段（实例化渲染、拖拽降级等）列为储备，待一期实测后回填（requirements §5、§11 开放问题 2），不在本 spec 承诺数字。

## Testing Decisions

- **模型状态层是主测试面（接缝 1 的编辑器应用）**：给定初始模型，执行每个受约束操作，断言结果模型与拒绝路径（非法操作不改变模型并返回原因）。全部纯逻辑测试，无渲染依赖。
- 交互组件（表单、选中、提示条）用组件测试验证其调用了正确的状态层操作；不测渲染像素。
- 渲染正确性（截面形状、颜色、材质显示）走人工可视化验收清单，不写自动化断言。
- 无既有先例；状态层测试模式将成为后续交互功能的范本。

## Out of Scope

- 自由 CAD 编辑（布尔、放样、任意变形）。
- 动画/爆炸图/材质 PBR 级渲染效果。
- 手机端适配的实现（仅架构预留）。
- 多人协作编辑。
- 性能量化指标（一期实测后回填）。

## Further Notes

- 编辑器的易用性是产品成败关键（目标用户 A 类零经验）；实施时建议配一个最小可用性走查（用户能否在无说明下完成"加层板、改尺寸"），此为验收加分项而非阻塞项。
- 受约束拖拽的吸附规则（栅格步长、槽位对齐）实施时与型材槽宽联动，具体数值实施时定。
